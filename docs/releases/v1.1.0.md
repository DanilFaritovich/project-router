# ProjectRouter v1.1.0

This version refines Danil Miftakhov's EN/RU portfolio around Python Backend
roles and adds six editable, role-specific resumes. It builds on completed
implementation stages 01–09 and the existing protected-main delivery process.

## Portfolio

- Python Backend is the primary direction; PostgreSQL, data processing and
  integrations support that positioning. Data / ETL and AI / LLM remain secondary
  resume variants.
- Three commercial case briefs describe batch address processing,
  supplier-to-Ozon stock synchronization and LLM-assisted geospatial-name localization.
  The reported run of up to 46 million records in approximately 6–8 hours is an
  owner-confirmed example, not an independently reproduced benchmark.
- Geocoder leads the featured projects, followed by Moon Courier Crisis and
  Support Assistant. The additional catalog retains Task Service API and MaximML;
  Avito Parser is removed from the displayed catalog.
- Portfolio Server Infrastructure and Portfolio Deployment appear as related
  projects with distinct source labels and host/application responsibilities.
  First-rollout status is explicitly operator-reported.
- EN/RU profile, skills and SEO copy follow the updated positioning.

## Resumes

Six new two-page PDFs cover Backend, AI / LLM and Data / ETL in EN/RU. Each role
has its own profile, skills ordering and four selected projects, including
Portfolio Deployment. The documents include portfolio and contact links.

The existing PDF viewer serves the new `candidate-*` assets and retains independent
document language, paging, zoom, fit width, download and error handling. Download
names consistently identify role and language. All six original PDFs remain
byte-for-byte unchanged.

Editable content is in `scripts/resumes/content.mjs`; layout and offline
generation are in `scripts/render-resumes.mjs`. `make resume-candidates` creates
PDF/HTML review artifacts in the system temporary directory without overwriting
public assets.

## Delivery and limitations

Release integration follows `develop → main`. Main publication uses the confirmed
build origin `https://danil-miftakhov.dev`. The operator verifies successful
same-SHA CI, the immutable image digest, both signed attestations, manager admission
and runtime acceptance through `portfolio-deployment`. Successful push CI on
`main` triggers `.github/workflows/deploy.yml`, which calls the pinned Manager
workflow; approving the release merge must account for this production CD path.
Tag/GitHub Release publication requires separate authorization. See the
[release checklist](../deployment/RELEASE-CHECKLIST.md) and
[deployment contract](../deployment/CONTRACT.md).

PDF text layer, search and selection remain outside scope; screen readers cannot
read prose from the viewer canvas. File download/fallback remains available.
Recorded automated browser coverage is Chromium/Linux; other browsers and
assistive technologies require separate checks. Local QA does not establish
current public HTTPS/SEO behavior, indexing, field performance or third-party
link availability.
