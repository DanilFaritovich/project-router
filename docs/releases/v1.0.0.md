# ProjectRouter v1.0.0 — draft release notes

Historical preparation notes. Current version scope and delivery guidance are in
the [v1.1.0 release notes](v1.1.0.md); the status statements below describe the
original preparation snapshot.

**Prepared, not published.** This is the proposed first release of Danil
Miftakhov's EN/RU engineering portfolio. Stages 01–09 are integrated into
`develop`; application metadata is `1.0.0`. There is no release date or confirmed
public deployment. Use these notes for the separately authorized GitHub Release
only after reviewing the actual main commit and its evidence.

## First-version scope

ProjectRouter brings professional experience, project source links, developer
tools, resumes and contacts into seven responsive sections. Its typed catalog
contains three featured projects, three additional projects and three tools,
with four real screenshots and explicit versioned release links where configured.
No public Live Demo is claimed.

The application uses Vue 3, TypeScript, Vite 8 and Tailwind CSS 4. Vue Router and
Vue I18n provide complete `/en/` and `/ru/` experiences with section/query/hash
preservation and browser history. Vite SSG and Unhead generate localized HTML and
metadata before JavaScript. An explicit HTTPS origin enables canonical/hreflang,
sitemap, social URLs and Person/WebSite JSON-LD. Content lives in Git; there is
no backend, database or request-time SSR.

Six unchanged owner-supplied PDFs cover Backend, AI / LLM and Data / ETL in both
languages. A lazy client-only PDF.js viewer provides independent document language,
pages, zoom, fit width, download, original-file fallback and error/retry handling.
Only HTTP(S)/mailto URL annotations are allowed; HTTP(S) uses safe new-tab
attributes, and PDF scripts/actions are excluded. Focus handling and resource
cleanup are part of the viewer/menu implementation.

## Quality and artifact delivery

ESLint, Prettier, vue-tsc, Vitest, built-HTML/asset tests and Chromium journeys
cover localization, navigation, responsive layouts and all six real PDFs.
The [Stage 07 QA report](../qa/STAGE07-REPORT.md) records automated results,
axe scans, browser captures, visual review and explicit acceptance limits;
its historical counts are not a claim about a future release SHA.

Digest-pinned Node → Nginx Unprivileged packaging serves static files as UID/GID
101:101 on HTTP 8080. Compose applies read-only root, tmpfs and capability
restrictions. CI validates the site and containers before trusted-push GHCR
publication. PRs do not publish; workflows do not deploy or create releases.

The publication workflow verifies registry digest/platform and embedded origin,
then signs SLSA provenance and a custom origin/build-input predicate through
GitHub OIDC/Sigstore. Release acceptance requires successful exact-SHA CI and both
verified attestations for the immutable digest, source/ref and trusted workflow.
An existing tag or unsigned metadata is insufficient. See the
[deployment contract](../deployment/CONTRACT.md).

## Known limits and production status

- The site is not deployed. `https://danil-miftakhov.dev` is the confirmed build
  origin, not evidence of public availability. Public HTTPS, redirects, live
  metadata, indexing and field performance remain unverified.
- `portfolio-deployment` owns application operations, gateway/Caddy, domain and
  networks; `portfolio-server-infrastructure` owns host provisioning/hardening.
  Current manager policy accepts protected-main artifacts only. The actual
  production digest/signatures, admission and runtime acceptance remain operator work.
- PDF text layer/search/selection is outside scope; screen readers cannot read
  PDF prose from the canvas. Original-file links remain available.
- Recorded browser QA covers Chromium/Linux. Firefox, Safari/iOS, physical devices
  and assistive-technology acceptance require owner checks. Automated axe results
  are not WCAG certification; external-link checks do not guarantee availability.
